# Памятка организаторам

В архиве находится исходный код и Docker-конфигурация MVP «Домовед». Он подходит для двух независимых способов проверки.

## 1. Проверка готового стенда

Диспетчерская доступна по адресу, который участники передают организаторам отдельно. Для входа нужны учётные данные администратора, также переданные **отдельным сообщением**.

Не добавляйте пароль работающего стенда в презентацию, Git, архив проекта или общий чат. Вход в диспетчерскую позволяет изменять заявки, дома, квартиры и рассылки.

После входа проверьте:

1. Очередь заявок и переключение «Архив».
2. Сортировку: по числу жителей и по дате создания.
3. Карточку заявки: статусы, будущий плановый срок, комментарий.
4. Дома, квартиры, аварийные службы и сообщения жителям.
5. Состояние backend в верхней панели — «доступен».

## 2. Самостоятельный локальный запуск с тестовыми данными

Требуются Docker Engine и Docker Compose v2. Node.js, PostgreSQL и локальные зависимости устанавливать не нужно.

```bash
unzip "Хакатон MAX - Умный город - матрешки.zip" -d smart-home-max
cd smart-home-max
cp .env.example .env
docker compose -f compose.yaml -f compose.demo.yaml up --build
```

Для проверки в браузере без MAX перед запуском укажите в `.env`: `MINIAPP_DEV_AUTH=true` и `PLATFORM_ADMIN_MAX_USER_IDS=900`. Тогда:

- `http://localhost:8080/app/?dev=1001` — житель (любой числовой id — отдельный пользователь);
- `http://localhost:8080/app/?dev=900` — администратор платформы: «Платформа» → пульт любой УК.

Паролей по умолчанию нет: в веб-диспетчерскую сотрудники входят по одноразовой ссылке из бота. Пошаговый сценарий и ожидаемый результат — в README, раздел «Пошаговый сценарий проверки».

Контейнер `seed` сам заполнит тестовую БД двумя домами, квартирами, жителями, автомобилями, службами и заявками. Полный формальный состав набора и фиксированные ID API-проверки приведены в [test-data.json](test-data.json). В этом режиме `MAX_MODE=fake`: сообщения не отправляются в MAX, а фиксируются в логах. Это намеренно — токен реального бота в пакет не включён.

Полезные команды:

```bash
# Посмотреть логи
docker compose -f compose.yaml -f compose.demo.yaml logs -f

# Остановить контейнеры
docker compose -f compose.yaml -f compose.demo.yaml down

# Полностью очистить только локальные тестовые данные
docker compose -f compose.yaml -f compose.demo.yaml down -v
```

## 3. Самостоятельный production-запуск

Подробная инструкция для VDS находится в [DEPLOY_VDS.md](DEPLOY_VDS.md). Нужны собственные домен, токен MAX и уникальные секреты. Скопируйте `.env.production.example` в `.env.production`, заполните все `REPLACE_WITH_…` и выполните production-команду из инструкции.

Ни текущая база данных, ни рабочие токены, ни пароль активной диспетчерской в архив не включены.
