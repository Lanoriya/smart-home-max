# Эксплуатация и данные

## Резервное копирование

Ежедневно сохраняйте сжатый custom-format dump PostgreSQL вне VDS и контролируйте срок хранения:

```bash
docker compose --env-file .env.production -f compose.yaml -f compose.production.yaml \
  exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' \
  > "backup-$(date +%F-%H%M).dump"
```

Минимум раз до демонстрации проверьте восстановление в отдельную тестовую БД. Не проверяйте restore поверх рабочей базы.

## Наблюдение

- `/health/live` проверяет процесс;
- `/health/ready` проверяет подключение к PostgreSQL;
- сообщения outbox со статусом `dead` означают, что пять попыток доставки исчерпаны;
- следите за свободным диском, сроком сертификата, ошибками MAX API и ростом таблиц `processed_updates`, `outbox_messages`, `admin_audit_events`.

## Персональные данные

Система хранит MAX user ID, ФИО, телефоны, адрес/квартиру, автомобили и содержание обращений. До реального пилота необходимо утвердить оператора данных, правовое основание, текст согласия, сроки хранения и процедуру удаления/выгрузки данных. Доступ к production-БД и резервным копиям должен быть ограничен назначенными сотрудниками УК.

В runtime не используются LLM или иные AI-сервисы; персональные данные во внешние AI API не передаются. Внешний сервис продукта — MAX Bot API.

## Секреты

`.env.production`, локальные `.env`, дампы БД и логи не передаются вместе с исходниками. При подозрении на утечку немедленно смените токен MAX, webhook-secret, пароль администратора, пароль БД и pepper кодов квартир.
