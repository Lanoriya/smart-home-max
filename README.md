# «Домовед» — чат-бот и мини-приложение MAX для дома и управляющей компании

Трек «Умный город». Рабочий бот: https://max.ru/t238_hakaton_max_bot · сайт и веб-диспетчерская: https://jorwey.ru

## Назначение

Житель многоквартирного дома сообщает о проблеме УК прямо в MAX и видит, что с ней происходит: зарегистрирована ли заявка, кто ею занимается, в какой срок она должна быть решена по закону и каков её статус. Соседи с той же проблемой не создают дубли, а присоединяются к общей заявке — УК видит одну карточку вместо десятка звонков, и чем больше жителей её подтвердили, тем выше она в очереди.

Вокруг этого ядра — то, что УК обязана давать жителям: объявления, контакты и номера служб, обязанности и сроки по закону, запись на приём, опросы жителей. Одна платформа обслуживает много УК; данные разных УК не смешиваются.

## Основной пользовательский сценарий

1. Житель открывает бота, выбирает город, дом и квартиру и подтверждает её **номером договора** или **кодом дома** (и личным кодом квартиры, если УК его задала). Перед первым подключением — согласие на обработку персональных данных.
2. «Сообщить о проблеме»: где (дом или квартира), что случилось, срочность, описание и до трёх фото. Если соседи уже сообщили о том же, сервис предлагает присоединиться к их заявке.
3. УК получает уведомление в MAX и работает с заявкой в пульте мини-приложения или в веб-диспетчерской: принимает, берёт в работу, назначает срок, пишет жителям, закрывает.
4. Все жители заявки получают каждое изменение в MAX. В карточке видны плановый срок УК и **срок по закону** с остатком времени; УК получает напоминание, когда остаётся четверть срока, и сообщение, если срок истёк. Каждый сотрудник может отключить эти напоминания для себя — в боте или в разделе «Ещё» mini-app.

## Состав и архитектура

| Компонент | Что делает |
|---|---|
| `apps/backend` (Node.js 22, Express 5, Prisma 6) | REST API бота, мини-приложения и диспетчерской; приём событий MAX (webhook); бизнес-логика |
| `apps/backend` worker | очередь исходящих сообщений с повторами; напоминания о сроках по закону |
| `apps/miniapp` (React 19, MAX UI, MAX Bridge, Leaflet) | мини-приложение MAX: житель, пульт УК, пульт платформы; отдаётся по пути `/app/` |
| `apps/admin-web` (React 19) | веб-диспетчерская УК и веб-админка платформы для работы с компьютера |
| PostgreSQL 16 | дома, квартиры, жители, заявки, опросы, запись на приём, очередь сообщений |
| nginx | единая точка входа: статика, `/api/`, `/webhooks/max`, кэш подложки карты `/tiles/` |

Подробная схема и решения — в [ARCHITECTURE.md](ARCHITECTURE.md). Контракт API — [docs/openapi.yaml](docs/openapi.yaml), обязательные проверки — [DATA-API.yaml](DATA-API.yaml).

Роли:

| Роль | Как получает доступ | Что доступно |
|---|---|---|
| Житель | любой аккаунт MAX | подключение к квартире, заявки, соседи (поиск владельца авто, сообщение другой квартире), опросы, запись на приём, объявления, службы, «Моя УК» |
| Сотрудник УК | ссылка-приглашение, открытая в MAX | пульт: заявки, дома и квартиры, коды и договоры, объявления, опросы, приём граждан, службы и быстрый набор, обязанности УК, команда, показатели; веб-диспетчерская по одноразовой ссылке из бота |
| Администратор платформы | MAX user_id в `PLATFORM_ADMIN_MAX_USER_IDS`; на сайте — также по логину и паролю | все УК и их показатели, подключение УК из реестра и её домов списком или по карте, передача домов, удаление УК, общий текст обязанностей УК и политики данных, пульт любой УК |

## Запуск одной командой

Нужны только Docker Engine и Docker Compose v2.

```bash
cp .env.example .env
# для проверки в браузере без MAX:
#   MINIAPP_DEV_AUTH=true
#   PLATFORM_ADMIN_MAX_USER_IDS=900
docker compose -f compose.yaml -f compose.demo.yaml up --build
```

После старта (сборка — около 3 минут без учёта загрузки базовых образов):

- мини-приложение: `http://localhost:8080/app/?dev=<любой числовой id>` — вход «как пользователь MAX с этим id» (только при `MINIAPP_DEV_AUTH=true`);
- веб-диспетчерская: `http://localhost:8080`.

Без `compose.demo.yaml` запускается чистая система без тестовых данных.

**Остановка и повторный запуск:**

```bash
docker compose -f compose.yaml -f compose.demo.yaml down       # остановить, данные сохраняются
docker compose -f compose.yaml -f compose.demo.yaml down -v    # остановить и удалить тестовую БД
docker compose -f compose.yaml -f compose.demo.yaml up -d      # снова запустить
docker compose -f compose.yaml -f compose.demo.yaml logs -f worker   # исходящие сообщения в режиме MAX_MODE=fake
```

Проверки исходников: `pnpm install && pnpm typecheck && pnpm test && pnpm build`.

## Переменные окружения

Полный список без секретов — в [.env.example](.env.example) (локально) и [.env.production.example](.env.production.example) (сервер).

| Переменная | Назначение |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | база данных |
| `MAX_MODE` | `fake` — без сети, сообщения пишутся в лог worker; `api` — настоящий MAX |
| `MAX_RECEIVE_MODE` | `none`, `polling` (разработка) или `webhook` (сервер) |
| `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`, `MAX_PUBLIC_WEBHOOK_URL` | доступ к MAX Bot API; не хранятся в репозитории |
| `MAX_BOT_USERNAME` | ник бота: кнопки «Открыть приложение», ссылки-приглашения |
| `MINIAPP_URL`, `MINIAPP_OPEN_MODE` | адрес мини-приложения; `open_app` или `link` |
| `PLATFORM_ADMIN_MAX_USER_IDS` | MAX user_id администраторов платформы |
| `MINIAPP_DEV_AUTH` | вход по `?dev=<id>` для локальной проверки; в production запрещён |
| `APARTMENT_CODE_PEPPER` | секрет для хеширования личных кодов квартир |
| `ADMIN_SESSION_TTL_HOURS`, `ADMIN_COOKIE_SECURE`, `ADMIN_WEB_ORIGIN` | сессии веб-диспетчерской |
| `GEOCODER_URL`, `SUGGEST_URL` | геокодер Nominatim и подсказки адресов Photon (по умолчанию публичные серверы OpenStreetMap) |
| `ADMIN_WEB_PORT` | локальный порт (по умолчанию 8080) |

## Порты

- локально: `127.0.0.1:8080` — nginx (сайт, `/app/`, `/api/`); backend (3000) и PostgreSQL (5432) наружу не публикуются;
- сервер: 80/443 — Caddy с автоматическим TLS перед nginx ([docs/DEPLOY_VDS.md](docs/DEPLOY_VDS.md)).

## Зависимости

Версии зафиксированы в [package.json](package.json) и [pnpm-lock.yaml](pnpm-lock.yaml) (pnpm workspace из трёх приложений). Все библиотеки — открытые (MIT/BSD/Apache): Express, Prisma, zod, React, MAX UI, Leaflet. Закрытых библиотек и частных API нет; генеративный ИИ в продукте не используется.

## Внешние сервисы и интеграции

| Сервис | Зачем | Без него |
|---|---|---|
| MAX Bot API | сообщения бота, кнопки, мини-приложение | локально заменяется `MAX_MODE=fake` |
| OpenStreetMap: тайлы карты | подложка карт; идёт через nginx с кэшем на месяц | карта без подложки |
| Nominatim, Photon (OpenStreetMap) | адрес по точке на карте, поиск адресов, точка офиса УК по адресу | дом ставится нажатием на карту, адрес вводится вручную |
| Открытые данные ППК «Фонд развития территорий» | реестр управляющих организаций и характеристики домов (этажность, год, квартиры) — загружаются файлами | УК и дома заводятся вручную |

Интеграций с ГИС ЖКХ и биллингом нет: в MVP это не имитируется.

## Работа с данными

- Хранятся: идентификатор и имя из MAX, адрес и квартира, заявки, комментарии и фото, телефон и автомобиль — только если житель сам их добавил; голоса в опросах (одна квартира — один голос); записи на приём.
- Перед первым подключением к квартире житель даёт согласие на обработку персональных данных (152-ФЗ); политику ведёт администратор платформы, жители читают её в приложении. «Отвязаться от квартиры» отзывает согласие: привязка, телефон и автомобили стираются.
- Запросы мини-приложения проверяются по подписи `initData` MAX; веб-диспетчерская — по одноразовой ссылке из бота (5 минут) или паролю администратора платформы (scrypt). Сессии — HttpOnly SameSite-cookie, в базе только хеши.
- Каждая выборка ограничена своей УК; чужая заявка, дом или квартира — 404. Действия сотрудников пишутся в журнал.
- Коды домов и квартир: код дома — 10 цифр, личный код квартиры хранится только как HMAC-хеш; пять неверных попыток в час — блокировка.

## Тестовые данные

`compose.demo.yaml` запускает наполнение — **все данные демонстрационные**:

- «Тестовая УК …» и «Демо-УК «<город>»» — вымышленные компании; телефоны и описания служб помечены «Демонстрационный номер»;
- реальные адреса домов пяти городов (Екатеринбург, Казань, Челябинск, Пермь, Новосибирск) взяты из открытых данных ФРТ и OpenStreetMap и закреплены за вымышленными «Демо-УК»; жильцы, автомобили и заявки — вымышленные;
- у всех тестовых домов код `0000000000`, у квартир — номер договора `0000000000` и личный код `000000`.

Состав набора — [docs/test-data.json](docs/test-data.json).

## Пошаговый сценарий проверки

Локально, с `MINIAPP_DEV_AUTH=true` и `PLATFORM_ADMIN_MAX_USER_IDS=900`:

1. `http://localhost:8080/app/?dev=1001` → «Карта» → нажмите на дом «Тестовый №1 Улица демонстрации, 10» → «Это мой дом» → квартира `5` → «Номер договора» `0000000000` → отметьте согласие → «Подтвердить». **Ожидается:** квартира подтверждена, на главной — адрес и кнопка «Сообщить о проблеме».
2. «Сообщить о проблеме» → «В доме» → «Лифт» → подъезд `1` → описание → «Отправить». Затем второй житель того же дома: `?dev=1002`, квартира `6`, тот же путь. **Ожидается:** второму жителю приложение предлагает присоединиться к заявке соседа (совпадения ищутся среди заявок, обновлённых за последние сутки); после «Я тоже» в заявке 2 жителя.
3. Откройте заявку. **Ожидается:** статус, плановый срок и «Срок по закону: осталось … ч» со ссылкой на постановление.
4. `http://localhost:8080/app/?dev=900` → «Платформа» → «Открыть пульт этой УК» на «Тестовая УК «Северная»» → «Заявки» → откройте ту же заявку → «В работу», срок, сообщение жителям. **Ожидается:** в логе `worker` — сообщения всем жителям заявки.
5. В пульте → «Опросы жителей» → «+ Опрос»: вопрос, 3 варианта, «Всем домам УК», анонимный. **Ожидается:** в логе `worker` — уведомления жителям; у жителя (`?dev=1001`) на вкладке «Опросы» точка; после голоса — проценты, но без номеров квартир; в пульте — какие квартиры за что голосовали.
6. В пульте → «Приём граждан» → откройте окна на завтра. Житель → «Главная» → «Запись на приём» → время и тема. **Ожидается:** запись в «Мои записи», в пульте — кто и с каким вопросом записан; повторная запись на то же время другим жителем — «Это время уже заняли».
7. Житель другой УК (`?dev=1003`, подключите его к дому «Демо-УК» любого города) не видит заявок, опросов и окон первой УК.

Бот проверяется в MAX: https://max.ru/t238_hakaton_max_bot (главное меню, «Сообщить о проблеме», «Мои заявки», «Опросы УК», «Запись на приём»).

## Примеры ожидаемого поведения

- Повторная проблема в том же месте за сутки → предложение присоединиться, а не новая заявка; на 3, 5 и 10 жителях приоритет растёт, УК получает сообщение.
- Неверный код дома 5 раз за час → «Слишком много неверных кодов. Попробуйте через час».
- Голос в опросе, где менять голос нельзя, → «В этом опросе голос нельзя изменить»; голос после окончания → «Опрос уже завершён».
- Удаление УК с домами → предупреждение с числом домов и жителей; после подтверждения удаляются дома, квартиры и заявки, сотрудники теряют доступ.
- Ошибка сети в приложении → сообщение и кнопка «Повторить»; работа продолжается без перезапуска.

## Известные ограничения

- Нет интеграции с ГИС ЖКХ и биллингом: связь «дом — УК» задаётся при подключении УК, начисления и показания счётчиков не входят в MVP.
- Демонстрационный сервер размещён за пределами РФ; для эксплуатации с реальными жителями хранение персональных данных нужно перенести на сервер в России (152-ФЗ).
- Публичные Nominatim и Photon ограничены по частоте запросов; для нагрузки нужен собственный геокодер.
- Сроки по закону — максимальные по постановлениям; более короткие сроки договора управления УК задаёт в своём тексте обязанностей, но не в расчёте сроков заявки.
- Опрос — инструмент учёта мнения жителей, а не юридически значимое общее собрание собственников.
- Списки в интерфейсе ограничены 100 заявками; полноценной пагинации нет.

## Обновление открытых данных

Реестр УК и дома загружаются из файлов открытых данных ФРТ:

```bash
pnpm --filter @smart-home/backend registry:import companies export-reestruo-00-YYYYMMDD.csv
pnpm --filter @smart-home/backend registry:import houses export-kr1_1-66-YYYYMMDD.csv
```

Портал ФРТ не отвечает зарубежным серверам; для сервера есть `scripts/update-registries.sh`, который скачивает файлы через временный SSH-туннель с компьютера в России (`scripts/fetch-ru.sh`). Бот, мини-приложение и карты от туннеля не зависят.
